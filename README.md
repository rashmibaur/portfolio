## Design System & Stack

This is a static site, not a framework app.

- **Homepage:** self-hosted export of the Framer site (`index.html`, `f/`). Animations run on Framer's own runtime.
- **Case studies:** hand-written HTML in `content/<slug>.html`, with metadata (title, tags, colours) in `content/projects.json`.
- **Styling:** one shared stylesheet, `css/case.css`. No CSS framework.
- **Interaction:** vanilla JS in `js/` (`charts.js`, `cards.js`, `steps.js`, `progress.js`, `links.js`).
- **Build:** Node script `scripts/build.mjs` generates each `<slug>/index.html` and crops slide images to WebP with `sharp`.
- **Charts:** generated by `scripts/*-charts.mjs` for the data-heavy studies.
- **Hosting:** Vercel, as a static site.
- **Accessibility:** no formal WCAG AA audit has been run on this site yet.

## Case Study Architecture

Data-led studies, such as Unveiling Biases in AI, follow one arc:

1. **Data architecture:** what the data is, where it comes from, how it is structured and what the metrics mean.
2. **Embedded AI / model mechanics:** how the model works (input, hidden and output layers), shown in the page, so the reader can see where bias or error enters.
3. **Interaction design:** the interface that makes the data and model behaviour usable, such as dashboards, audit views and tables.

Each page also carries the project's tags, time, team and tools from `projects.json`.

## Embedding Functional Prototypes

No prototypes are embedded yet. The intended pattern for adding one:

- A responsive iframe container with a fixed aspect ratio, so the prototype scales with the page.
- A device frame (phone, tablet or desktop) around the iframe.
- A full-screen toggle that opens the prototype at full viewport size.

## Local Setup

```
npm install
npm run dev      # builds the case studies, serves on http://localhost:8000
npm run build    # only rebuilds <slug>/index.html and img/
```

Requires Node 18+.
